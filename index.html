Passo 1 - Criar o Apps Script na planilha
Na planilha: Extensoes → Apps Script → apague o codigo existente → cole o codigo abaixo → Salvar → Implantar → Nova implantacao → Tipo: App da Web → Acesso: Qualquer pessoa → Implantar → copie a URL gerada.
function doGet(e) { var ss = SpreadsheetApp.getActiveSpreadsheet(); var aba = e.parameter.aba || "Sprints"; var sheet = ss.getSheetByName(aba); if (!sheet) return ContentService.createTextOutput("[]").setMimeType(ContentService.MimeType.JSON); var data = sheet.getDataRange().getValues(); var headers = data[0]; var rows = data.slice(1).map(function(row) { var obj = {}; headers.forEach(function(h, i) { obj[h] = row[i]; }); return obj; }); var out = ContentService.createTextOutput(JSON.stringify(rows)); out.setMimeType(ContentService.MimeType.JSON); return out; }
Passo 2 - Cole a URL aqui
Salvar permanentemente: Abra o .html no Bloco de Notas, localize const URL_FIXA = '' e cole sua URL entre as aspas.

Como configurar a planilha e publicar online

Google Sheets + Apps Script como fonte de dados - GitHub Pages para publicacao gratuita

PASSO 1 Criar as abas no Google Sheets
1.Acesse sheets.google.com e crie uma nova planilha
2.Aba Sprints - cabecalhos na linha 1 (sem Lead Time, que fica em aba propria):
SprintModuloHUs_EntreguesHUs_Planejadas_SprintHUs_ReabertasHUs_Entregues_TotalAging_HUHUs_Priorizadas
S1Modulo A913414185
S2Modulo A1113314157
!Entregas_% = (HUs_Entregues / HUs_Planejadas_Sprint) x 100 — calculado automaticamente. Retrabalho_% = (HUs_Reabertas / HUs_Entregues_Total) x 100 — calculado automaticamente. Aging_HU = maior numero de dias que qualquer HU permaneceu no mesmo status (backlog → em desenvolvimento) na sprint.: (HUs_Entregues / HUs_Planejadas_Sprint) x 100. Nao e necessario inserir a coluna Entregas_% se preencher HUs_Entregues e HUs_Planejadas_Sprint.
3.Aba LeadTime_HUs - cada linha e uma HU individual (sem vinculo com sprint):
HUModuloFeatureData_InicioData_AceiteLeadTime_dias
HU-001Modulo AFeature X01/01/202515/01/2025=DIAS(E2,D2)
HU-002Modulo AFeature Y20/01/202510/03/2025=DIAS(E3,D3)
!O eixo X do grafico usa Data_Aceite. Uma HU pode cruzar varias sprints sem problema. IMPORTANTE: Esta aba agora tambem alimenta o grafico "Requisitos Levantados" (mostra apenas HUs com Data_Aceite preenchida).
4.Aba Retrabalho - indicador de HUs reabertas com agrupamento mensal:
SprintModuloData_EntregaHUs_ReabertasHUs_Entregues_Total
S1Modulo A15/01/2025414
S2Modulo A30/01/2025314
S3Modulo B14/02/2025213
!Data_Entrega: data de encerramento da sprint (obrigatoria) - usada para agrupar os dados por mes. % Retrabalho = (HUs_Reabertas ÷ HUs_Entregues_Total) × 100 — calculado automaticamente por mes no grafico. Sprints do mesmo mes sao somadas automaticamente. HUs_Reabertas: quantidade de HUs que precisaram ser reabertas apos entrega. HUs_Entregues_Total: total de HUs entregues na sprint.
5.Aba Aging - indicador de tempo de estagnacao das HUs por sprint:
SprintModuloAging_HU
S1Modulo A18
S2Modulo A15
S3Modulo B12
!Aging_HU: numero de dias que a HU permaneceu no mesmo status (de Backlog ate Em Desenvolvimento). Meta: <= 15 dias. Objetivo: Detectar atraso oculto por estagnacao no fluxo de trabalho. Periodicidade: Semanal (uma medicao por sprint/semana).
6.Aba Homologacao - apenas 2 linhas, uma por status, com o total de HUs:

Modulo AHomologadas18

Modulo BHomologadas12
Modulo BDevolvidas3
7.Aba Capacity - horas por funcao por sprint:
SprintModuloFuncaoDisponivelPlanejado
S1Modulo AFront-end4032
S1Modulo ABack-end4840
S1Modulo BQA2416
!Funcoes aceitas: UX/UI, Banco de Dados, Requisitos, Front-end, Back-end, QA
8.Aba Roadmap - estrutura de arvore do projeto (Modulo > Feature > HU):
ModuloFeatureHUData_InicioData_FimStatus
Modulo AFeature XHU-00105/01/202518/01/2025Concluido
Modulo AFeature XHU-00215/01/202528/01/2025Concluido
Modulo AFeature YHU-00301/02/202520/02/2025Em andamento

!Uma linha por HU. As barras de Modulo e Feature sao calculadas automaticamente pelo periodo das HUs filhas. Status aceitos: Concluido, Em andamento, Planejado. Sem Status = Planejado.
9.Aba Burndown_Escrita - ritmo de escrita e refinamento de requisitos:
HUModuloFeatureData_InicioData_Aceite
HU-001Modulo AFeature X05/01/202510/01/2025
HU-002Modulo AFeature X08/01/202515/01/2025
HU-003Modulo BFeature Y12/01/202520/01/2025
!Objetivo: Avaliar ritmo de escrita e refinamento de requisitos. Periodicidade: Quinzenal (agrupamento automatico por Data_Aceite). Grafico: Comparacao entre HUs planejadas × HUs efetivamente escritas ao longo do tempo. Linha de tendencia linear mostra o ritmo ideal. HUs sao contadas apenas quando tem Data_Aceite preenchida (refinamento completo).
10.Aba Burndown_Dev - ritmo de desenvolvimento e previsibilidade:
SprintModuloHUs_EntreguesHUs_Planejadas_Sprint
S1Modulo A1013
S2Modulo A1113
S3Modulo B1213
!Objetivo: Avaliar ritmo de desenvolvimento e previsibilidade. Periodicidade: Quinzenal (por sprint). Grafico: Colunas empilhadas mostrando HUs Entregues (verde) + HUs Restantes (cinza) por sprint. Total planejado = soma de todas as HUs_Planejadas_Sprint. Linha de tendencia linear (amarela) mostra o ritmo ideal. Meta: linha real abaixo da tendencia.
PASSO 2 Criar o Apps Script (ponte de dados)
1.Na planilha: Extensoes → Apps Script
2.Apague o codigo existente e cole o script abaixo:
function doGet(e) { var ss = SpreadsheetApp.getActiveSpreadsheet(); var aba = e.parameter.aba || "Sprints"; var sheet = ss.getSheetByName(aba); if (!sheet) return ContentService.createTextOutput("[]").setMimeType(ContentService.MimeType.JSON); var data = sheet.getDataRange().getValues(); var headers = data[0]; var rows = data.slice(1).map(function(row) { var obj = {}; headers.forEach(function(h, i) { obj[h] = row[i]; }); return obj; }); var out = ContentService.createTextOutput(JSON.stringify(rows)); out.setMimeType(ContentService.MimeType.JSON); return out; }
3.Salvar → Implantar → Nova implantacao
4.Tipo: App da Web | Acesso: Qualquer pessoa → Implantar
5.Copie a URL gerada (comeca com https://script.google.com/macros/s/...)
PASSO 3 Conectar ao Dashboard
1.Clique em Reconfigurar no canto superior direito
2.Cole a URL do Apps Script e clique Conectar
3.Para salvar permanentemente: abra o .html no Bloco de Notas, localize const URL_FIXA = '' e cole a URL entre as aspas
PASSO 4 Publicar Online - GitHub Pages (gratuito)
1.Crie conta em github.com → New repository → nome: dashboard-montreal → Public → Create
2.Upload do arquivo, renomeie para index.html → Commit changes
3.Settings → Pages → Branch: main → Save → link ativo em ~2 min: seunome.github.io/dashboard-montreal
ROTINA Como atualizar os dados
-Sprints: adicione uma linha nova a cada sprint encerrada
-LeadTime_HUs: adicione uma linha por HU aceita, com as datas reais
-O cliente recarrega a pagina e ja ve os dados atualizados automaticamente
-Novo modulo: adicione o nome na coluna Modulo - o filtro aparece automaticamente
